# Example deployment (demo data — not a real school)

This folder is a **worked example** of what `/design-system` → `/build-flow` (×4) →
`/finalize-deliverables` produce, using placeholder school data (see `docs/system-plan.md`
for exactly what's fake). It exists so you can see and import a working n8n system without
running the interview yourself first.

It is **not** part of the reusable agent template — the skills always write to `sql/`,
`docs/`, and `workflows/` at the project root, never here. Using this agent for a real school:

1. Ignore or delete this folder.
2. Run `/design-system` from the project root with your school's real parameters.
3. Run `/build-flow` for each flow, `/finalize-deliverables` once they're built.

## What's here

- `sql/schema.sql` — tested against a real local PostgreSQL 16 instance (`psql -f`), all 11
  tables + 7 indexes create cleanly.
- `docs/system-plan.md` — the approved plan, with every placeholder value labeled «نمونه».
- `workflows/flow-0-error-handler.json`, `flow-1-public.json`, `flow-2-parents.json`,
  `flow-3-school-to-parent.json` — importable n8n JSON. Each one passed the real `flow-auditor`
  subagent (all 7 checks) via `python3 eval/run_eval.py .` runs, not just a manual read-through.
- `docs/SETUP.md`, `docs/TEST-CHECKLIST.md` — generated by `/finalize-deliverables` against
  this example's plan.

## Known simplifications (read before importing)

- Node `parameters` blocks are structurally correct (types, connections, credentials
  placeholders) but hand-authored — n8n's exact per-node-version parameter schema can differ
  slightly across n8n releases. After import, expect to re-pick credentials and spot-check
  Switch/IF condition syntax in the editor; this is normal for hand-authored n8n JSON.
- `first_reply_at` assumes a "پاسخ داده شد" button convention (see `system-plan.md`'s open
  questions) — confirm this matches how your staff will actually work before relying on the
  SLA timers.
- Flow 3's announcement/absence intake uses n8n's built-in Form Trigger (no separate admin
  panel, no domain/SSL) — a real staff-facing web UI would be a separate, larger project.
