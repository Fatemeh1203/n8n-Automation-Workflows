# راهنمای راه‌اندازی

> این راهنما برای همان دیپلویمنت نمونه‌ی مستندشده در `docs/system-plan.md` است (داده‌های
> ساختگی، برای دمو). قبل از استقرار واقعی، `/design-system` را با پارامترهای واقعیِ مدرسه
> اجرا کنید تا این مقادیر بازنویسی شوند.

## ۱. متغیرهای محیطی (n8n)

این مقادیر را به‌صورت متغیر محیطی n8n (یا credential نودهای Postgres/HTTP) تنظیم کنید —
هرگز داخل JSON یک workflow هاردکد نشوند:

| متغیر | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | از @BotFather — مرحله‌ی ۲ زیر. |
| `PG_HOST`, `PG_PORT`, `PG_DATABASE`, `PG_USER`, `PG_PASSWORD` | اتصال PostgreSQL داخلی مدرسه. |
| `OFFICE_CHAT_ID` | `-1001111111111` (نمونه) — دریافت‌کننده‌ی سرنخ‌های Flow 1. |
| `PRINCIPAL_CHAT_ID` | `-1002222222222` (نمونه) — دریافت‌کننده‌ی هشدار SLA ۲۴ساعته و گزارش هفتگی Flow 2/3. |

## ۲. ساخت بات تلگرام

1. یک چت با **@BotFather** در تلگرام باز کنید.
2. `/newbot` → یک نام و یک username یکتا که به `bot` ختم شود بدهید.
3. BotFather یک توکن برمی‌گرداند — همان `TELEGRAM_BOT_TOKEN` است. فقط در متغیر محیطی/
   credential خود n8n ذخیره شود، هرگز در فایلی که commit می‌شود.
4. `/setprivacy` → اگر کارکنان قرار است در یک گروه با بات تعامل کنند **غیرفعال** کنید (تا بات
   همه‌ی پیام‌های گروه را بخواند، نه فقط دستورها)؛ برای چت‌های ۱:۱ با اولیا پیش‌فرض (فعال) کافی است.
5. نیازی به تنظیم webhook نیست — این سیستم با `getUpdates` پول می‌کند، پس مراحل webhook و هر
   تنظیم دامنه/SSL در BotFather را رد کنید.

## ۳. راه‌اندازی پایگاه‌داده

1. دیتابیس را بسازید، سپس `sql/schema.sql` را روی آن اجرا کنید: `psql -f sql/schema.sql`.
2. جدول `students` را seed کنید: یک ردیف به‌ازای هر دانش‌آموز، همراه `unique_code` — این کدها
   را کوتاه و تصادفی‌الفبایی-عددی (مثلاً ۶ کاراکتر) و منحصربه‌فرد برای هر دانش‌آموز بسازید و از
   طریق کانال فعلیِ مدرسه (نه از طریق همین بات، تا کد به chat_id اشتباه لو نرود) به اولیا بدهید.
3. جدول `staff` را seed کنید — طبق فهرست نمونه‌ی زیر (این‌ها داده‌ی دمو هستند، با کارکنان واقعی
   جایگزین شوند):

   | نام | chat_id | دسته |
   |---|---|---|
   | علی رضایی | `111111111` | مالی |
   | سارا احمدی | `222222222` | آموزشی |
   | محمد کریمی | `333333333` | انضباطی |
   | زهرا موسوی | `444444444` | مرخصی |
   | — | — | سایر (بدون مسئول اختصاصی → پیش‌فرض به دفتر ارسال می‌شود) |

4. جدول `bot_offset` را seed کنید — چون Flow 1 و Flow 2 یک بات مشترک را با offset مستقل
   poll می‌کنند (به تصمیم معماری در `docs/system-plan.md` رجوع کنید)، هر دو ردیف لازم است:

   ```sql
   INSERT INTO bot_offset (bot_name, last_update_id) VALUES ('flow1', 0), ('flow2', 0);
   ```

   بدون این ردیف‌ها، اولین فراخوانی `getUpdates` هیچ `offset`ی برای شروع ندارد.
   `verification_attempts`، `sla_alerts` و `error_log` نیازی به ردیف اولیه ندارند — خالی
   شروع می‌شوند.

5. جدول `faq` را با چهار پاسخ منوی عمومی (شهریه / ثبت‌نام / درباره‌ی مدرسه / آدرس و ساعت کاری)
   seed کنید، با `keywords` نرمال‌شده — طبق `.claude/rules/persian-normalization.md` کلیدواژه‌ها
   را از قبل نرمال ذخیره کنید تا تطبیق زمان اجرا نرمال-به-نرمال باشد.

## ۴. ایمپورت workflowها

1. در n8n: Workflows → Import from File → هر فایل `workflows/flow-*.json` را به‌ترتیب ایمپورت
   کنید: ابتدا `flow-0-error-handler.json`، سپس `flow-1-public.json`، `flow-2-parents.json`،
   `flow-3-school-to-parent.json`.
2. در تنظیمات هر workflow ایمپورت‌شده (به‌جز خودِ error handler) → Settings → Error Workflow را
   روی `flow-0-error-handler` بگذارید.
3. credential نود Postgres هر workflow را به اتصال دیتابیس مدرسه ست کنید؛ URL نودهای HTTP
   Request را طوری بگذارید که از `{{$env.TELEGRAM_BOT_TOKEN}}` استفاده کنند، نه یک توکن ثابت.
4. هر ۴ workflow را Activate کنید.

## ۵. تست دود (Smoke test)

پیش از استفاده‌ی گسترده، مسیر طلایی (golden path) هر جریان را دستی اجرا کنید — به
`docs/TEST-CHECKLIST.md` مراجعه کنید.
