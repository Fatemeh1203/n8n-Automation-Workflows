# چک‌لیست تست دستی

شامل هر سه جریان به‌علاوه‌ی مدیریت خطای مشترک — همه در `workflows/` موجودند. هر مورد یک عمل
و نتیجه‌ی مورد انتظارِ رو‌به‌کاربر (فارسی) را مشخص می‌کند.

## جریان یک - عمومی (`workflows/flow-1-public.json`)

- [ ] `/start` → منوی inline با ۵ دکمه نمایش داده شود.
- [ ] تپ روی «شهریه» → پاسخ صحیح از جدول `faq`.
- [ ] تپ روی هر یک از ۳ دکمه‌ی دیگر → پاسخ صحیح.
- [ ] تپ روی «سؤال دیگر» → بات درخواست شماره تلفن کند.
- [ ] ارسال شماره تلفن (با اعداد فارسی، مثلاً ۰۹۱۲...) → درست نرمال‌سازی شود، رکورد در `leads`
      ثبت شود، دفتر بلافاصله هشدار دریافت کند.
- [ ] ارسال متن نامرتبط بدون تعامل با منو → رکورد در `unanswered` ثبت شود، کاربر پاسخ عمومی
      «متوجه نشدم» بگیرد، نه stack trace.
- [ ] ارسال یک پیام تلگرام دقیقاً دو بار پشت‌سرهم (شبیه‌سازی retry) → فقط یک رکورد در `leads`.

## جریان دو - اولیا (`workflows/flow-2-parents.json`)

- [ ] chat_id جدید هر متنی بفرستد → بات درخواست کد یکتا کند.
- [ ] کد اشتباه وارد شود → پاسخ خطا، شمارنده‌ی تلاش افزایش یابد.
- [ ] کد اشتباه ۳ بار وارد شود → پیام قفل؛ تلاش چهارم در همان یک ساعت هم با همان پیام قفل رد
      شود (نه با پیام «کد اشتباه» چهارم).
- [ ] پس از پایان قفل (یا پاک‌سازی دستی)، کد درست وارد شود → `parents.verified_at` ثبت شود،
      منوی دسته‌بندی نمایش داده شود.
- [ ] در هر ۵ دسته یک تیکت ثبت شود → رکورد در `tickets`، `assignee` صحیح طبق `staff.category`،
      شماره‌ی تیکت به ولی بازگردد.
- [ ] همان update دوباره ارسال شود (شبیه‌سازی retry در `getUpdates`) → رکورد تکراری در
      `tickets` ساخته نشود.
- [ ] دسته‌ای که مسئول ندارد → به‌صورت پیش‌فرض به دفتر ارسال شود، بی‌صدا حذف نشود.
- [ ] تیکتی بیش از ۴ ساعت بی‌پاسخ بماند → مسئول دقیقاً یک یادآوری بگیرد (نه یکی در هر ساعت).
- [ ] تیکتی بیش از ۲۴ ساعت بی‌پاسخ بماند → مدیر دقیقاً یک هشدار بگیرد.
- [ ] تیکت بسته شود → نظرسنجی دو دکمه‌ای ارسال شود؛ تپ روی هرکدام `tickets.rating` را ثبت کند.
- [ ] برای chat_id با `verified_at IS NULL`، هیچ مسیر داده‌ی دانش‌آموزی چیزی برنگرداند.

## جریان سه - مدرسه به ولی (`workflows/flow-3-school-to-parent.json`)

- [ ] اطلاعیه‌ای برای یک پایه ارسال شود → همه‌ی اولیای تأییدشده‌ی آن پایه دریافت کنند؛ اولیای
      خارج از آن پایه دریافت نکنند.
- [ ] اطلاعیه‌ای برای یک کلاس خاص ارسال شود → فقط اولیای تأییدشده‌ی همان کلاس دریافت کنند.
- [ ] یک غیبت ثبت شود → همان روز پیام به ولی درست برسد، با تاریخ شمسی فرمت‌شده‌ی صحیح.
- [ ] غیبت برای دانش‌آموزی که هنوز ولی تأییدشده ندارد → به‌عنوان یک شکاف ثبت شود، بی‌صدا از
      دست نرود.
- [ ] گزارش پنج‌شنبه ۱۸:۰۰ اجرا شود (یا منتظرش بمانید) → مدیر تعداد تیکت به تفکیک دسته،
      میانگین زمان اولین پاسخ هر واحد، تعداد تیکت‌های باز و پرتکرارترین موضوع را با تاریخ شمسی
      صحیح دریافت کند.

## حالت‌های خطای مشترک (هر جریان، از طریق `workflows/flow-0-error-handler.json`)

- [ ] خطای یک نود عمداً ایجاد شود (مثلاً credential دیتابیس موقتاً خراب شود) → جریان خطا آن را
      ثبت کند و کاربر (در صورت مشخص‌بودن chat_id) فقط پیام عمومی فارسی بگیرد، هرگز stack trace.
- [ ] جریان restart شود (شبیه‌سازی راه‌اندازی مجدد n8n) → polling از جدول آفست از آخرین
      `update_id` پردازش‌شده ادامه یابد، پیام‌های قبلاً پردازش‌شده دوباره پردازش نشوند.
